# 认证与授权

## 1. Context（背景）

系统自带 Web 账号体系（与应用内 SSH 登录凭据相互独立）。首次启动进入「初始化」流程创建管理员；此后通过 用户名 + 密码 + 图形验证码 登录，会话由 tower-sessions Cookie 承载。管理员可管理用户（创建 / 删除 / 冻结 / 重置密码 / 授予管理员）。密码安全采用「前端 SHA-256 → 后端 Argon2id」双层哈希。

## 2. Goals（目标）

- 未初始化系统时，任意访问引导至初始化页；初始化后仅登录用户可访问业务功能。
- 登录失败与验证码错误给出明确但安全的反馈；验证码一次性有效。
- 冻结（is_disabled）用户即使持有有效 Cookie 也无法访问任何受保护接口。
- 管理员操作永远无法制造「零管理员」或「自我锁死」状态。

## 3. Non-Goals（非目标）

- 不做注册页/找回密码/邮箱验证。
- 不做 OAuth / LDAP / SSO / 2FA。
- 不做登录失败次数限制与锁定（当前靠验证码缓解暴力破解）。
- 不做「记住我」多会话等级区分（统一 OnInactivity TTL）。

## 4. Constraints（约束）

### 路由清单

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET  | /api/auth/status   | 公开 | 返回 `{"needs_setup": bool}` |
| GET  | /api/auth/captcha  | 公开（会话） | 签发验证码图片 data URL，答案存 session |
| POST | /api/auth/setup    | 公开（一次性） | 创建第一个管理员；已有用户则 409 |
| POST | /api/auth/login    | 公开 | 用户名 + 密码（SHA-256 hex）+ 验证码 |
| POST | /api/auth/logout   | 会话 | flush session，返回 `{"ok": true}` |
| GET  | /api/auth/me       | RequireUser | 返回 `{id, username, is_admin}` |
| POST | /api/auth/password | RequireUser | 修改自己的密码 |
| GET  | /api/users          | AdminUser | 用户列表（UserInfo，无哈希） |
| POST | /api/users          | AdminUser | 创建用户 |
| GET  | /api/users/{id}     | AdminUser | 用户详情 |
| PUT  | /api/users/{id}     | AdminUser | 授予/撤销管理员 |
| DELETE | /api/users/{id}    | AdminUser | 删除用户 |
| POST | /api/users/{id}/password | AdminUser | 管理员重置密码 |
| POST | /api/users/{id}/freeze | AdminUser | 冻结（禁用）账号 |
| POST | /api/users/{id}/unfreeze | AdminUser | 解冻账号 |

### MUST

- **验证码前置**：`login` 必须先校验验证码（大小写不敏感、忽略首尾空白），无论校验结果如何 MUST 立即从 session 移除 `captcha_text`（一次性，防重放）；验证码错误返回 400「验证码错误」。
- **密码传输**：前端 MUST 对密码做 SHA-256（hex）后再传输；后端对收到的值再做 Argon2id 哈希存储；验证时按同一链路（前端哈希值 → Argon2id verify）。
- **校验规则**：用户名 3–32 字符（trim 后）、密码 ≥ 6 位；setup 复用同一套规则；`setup` 仅在 `count_users == 0` 时可用，否则返回 409。
- **错误不泄露枚举**：登录时用户不存在 / 密码错误 MUST 统一返回 401（不得区分「用户不存在」与「密码错误」）；禁用用户登录返回 403。
- **会话键**：用户 id 存于 session key `user_id`；`AuthUser` 仅取 id，`RequireUser` 加载完整用户且 MUST 拒绝 `is_disabled`（403），`AdminUser` 在 RequireUser 之上再要求 `is_admin`（403）。
- **用户管理安全规则**：管理员 MUST NOT 删除/冻结/撤销管理员身份的目标是自己；MUST NOT 删除或降级「最后一个管理员」（返回 409 Conflict）；删除用户后其连接配置随外键 CASCADE 清理。
- **改密**：`change_password` 必须先用旧密码（已哈希值）验证（错误返回 400「原密码错误」），新密码 ≥ 6 位；管理员重置密码同样 ≥ 6 位。
- **响应脱敏**：所有用户相关响应 MUST NOT 包含 `password_hash`；`users` 列表字段固定 `{id, username, is_admin, is_disabled, created_at}`。
- **session 错误**：session 读写失败 MUST 统一映射为 401/500 而非泄露原始错误（见 `session_err`）。

### MUST NOT

- MUST NOT 在日志中打印密码（任何形态：明文、SHA-256、Argon2 哈希）。
- MUST NOT 允许已登录用户停留在 `/login`、`/setup` 路由（前端路由守卫，见 0005）。
- MUST NOT 在 `login` 失败路径区分用户名不存在与密码错误。
- MUST NOT 让 setup 在已有用户时静默覆盖或追加第二个管理员。

### SHOULD

- 验证码每次请求签发新图；图片为 160×60 PNG data URL，4 字符，带 Noise/Wave/Dots 干扰。
- 冻结用户后主动记录 WARN 日志（含操作者与目标 id）便于审计。
- `me` 接口被前端作为会话有效性探针，返回体保持最小字段集。

## 5. Decisions Made（已定决策）

- 验证码实现：`captcha` crate 1.0（`captcha_text` session 键，小写存储）。
- 密码哈希参数：`Argon2::default()`（Argon2id，随机 salt），哈希串存 `users.password_hash`。
- 初始化流程：`needs_setup = (用户数 == 0)`，由 `/auth/status` 公开探测；前端据此路由到 Setup 页。
- 用户禁用采用软删标记 `is_disabled`（迁移 0002），不动 session 存储（RequireUser 实时拒绝）。
- `USER_ID_KEY = "user_id"`（auth 模块常量），其他模块不得另起键名。

## 6. Task Breakdown（任务分解）

1. **会话与提取器**：`auth/extractors.rs`（AuthUser / RequireUser / AdminUser）——所有领域的依赖，先改。
2. **认证端点**：`auth/mod.rs`（setup / login / logout / me / password / captcha）。
3. **用户管理**：`users/mod.rs` + `db/models.rs` 用户查询族（list / create / delete / set_admin / set_disabled / update_password）。
4. **前端**：`stores/auth.ts` 状态机 + `router/index.ts` 守卫 + `LoginView / SetupView / PasswordView / UsersView`。
5. **验证**：Verifier 按第 7 节清单执行。

## 7. Verification Criteria（验收标准）

- [ ] 空库首次访问 `/auth/status` 返回 `needs_setup=true`；`POST /api/auth/setup` 创建管理员并直接登录；再次调用返回 409。
- [ ] 验证码：连续两次使用同一验证码登录，第二次返回 400「验证码错误」。
- [ ] 密码链路：前端 `sha256Hex(pw)` 值传输，DB 中 `password_hash` 为 Argon2id 串（`$argon2id$` 前缀），库中不存在任何形式的原始密码。
- [ ] 错误枚举：对不存在用户与错误密码登录均返回 401 同一文案。
- [ ] 冻结流：管理员冻结用户 → 该用户已有 Cookie 访问 `/auth/me` 返回 403；重新登录返回 403；解冻后恢复。
- [ ] 自我保护：管理员对自身执行 删除/冻结/撤销管理员 均被拒（400）；当系统仅剩一个管理员时，删除/降级该管理员返回 409。
- [ ] 越权：非管理员访问 `/api/users` 全部路由返回 403。
- [ ] `GET /api/users` 响应 JSON 中不存在 `password_hash` 字段（可对响应体做字符串断言）。
